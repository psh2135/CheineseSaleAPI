מהם השלבים המדויקים כדי להפעיל אותו במחשב אחר, שלא עליו עבדתי

כדי להפעיל פרויקט .NET ו-Angular במחשב אחר, יש כמה שלבים שצריך לעבור. הנה מדריך כללי:

1. התקנת כלים דרושים:

.NET SDK: אם לא מותקן, יש להוריד ולהתקין את ה-.NET SDK מאתר מיקרוסופט:
https://dotnet.microsoft.com/download

Node.js ו-NPM: יש להוריד ולהתקין את Node.js, שהוא גם כולל את NPM (החבילה לניהול תלויות של Angular):
https://nodejs.org/

Angular CLI: ניתן להתקין את Angular CLI עם הפקודה:

npm install -g @angular/cli

2. שכפול (Clone) הפרויקט מ-Git:

אם הפרויקט מאוחסן ב-Git, יש לשכפל אותו למחשב החדש:

git clone <URL של המאגר>
cd <שם התיקייה>

3. התקנת תלויות פרויקט (Dependencies):

חלק .NET: יש לעבור לתיקיית ה-backend (שם נמצא קובץ ה-.csproj) ולהריץ את הפקודה:

dotnet restore


חלק Angular: יש לעבור לתיקיית ה-Angular (שם נמצא ה-package.json) ולהריץ את הפקודה:

npm install

4. הגדרת סביבות הפיתוח (Environment):

במידה ויש קבצי קונפיגורציה שמכילים הגדרות סביבה כמו חיבורי API או פרמטרים אחרים, יש לוודא שהם קיימים או מעודכנים במחשב החדש.

5. בניית הפרויקט:

.NET Backend: יש לבנות את החלק של ה-.NET עם הפקודה:

dotnet build


Angular Frontend: יש לבנות את החלק של Angular עם הפקודה:

ng build --prod

6. הפעלה מקומית:

.NET Backend: ניתן להריץ את ה-backend ב-API או בשרת עם הפקודה:

dotnet run


Angular Frontend: ניתן להריץ את ה-Angular בשרת פיתוח עם:

ng serve

7. בדיקות:

עכשיו, כששני החלקים פועלים, כדאי לוודא שהמערכת פועלת כראוי:

ה-API של .NET פועל על הכתובת שצוינה (לרוב ב-http://localhost:5000).

החלק של Angular פועל ב-http://localhost:4200.

אם כל הצעדים הללו בוצעו בהצלחה, הפרויקט אמור לפעול במחשב החדש שלך.

מה עם הדאטהבייס? (SQL)

השלב של הגדרת הדאטהבייס הוא חשוב מאוד כדי שהפרויקט יפעל בצורה תקינה במחשב חדש. יש לוודא שהדאטהבייס מאופס, מוגדר כראוי ומחובר נכון לפרויקט. הנה השלבים הבסיסיים:

1. התקנת SQL Server או מערכת ניהול הדאטהבייס המתאימה:

אם אתה משתמש ב-SQL Server, יש לוודא שמערכת ה-SQL מותקנת על המחשב החדש. אם לא, ניתן להוריד ולהתקין את SQL Server Express
 או להשתמש בגרסה אחרת.

אם משתמשים במערכת אחרת כמו MySQL או PostgreSQL, יש להתקין את המערכת המתאימה.

2. שחזור בסיס הנתונים:

אם הדאטהבייס כבר קיים ויש לך גיבוי שלו (למשל קובץ .bak או סקריפטים ליצירת הבסיס):

SQL Server: ניתן לשחזר את הדאטהבייס עם הפקודה:

RESTORE DATABASE YourDatabase
FROM DISK = 'C:\path\to\your\backup.bak'


אם מדובר ביצירת בסיס נתונים חדש, עליך להריץ את הסקריפטים שמייצרים את הטבלאות והמבנה.

3. הגדרת חיבור לדאטהבייס בקובץ הקונפיגורציה:

.NET Backend: יש לוודא שבקובץ הקונפיגורציה של ה-.NET (appsettings.json או כל קובץ אחר שתגדיר), הוגדר חיבור תקין לדאטהבייס, למשל:

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=YourDatabase;User Id=yourusername;Password=yourpassword;"
  }
}

4. ביצוע מיגרציות (אם יש צורך):

אם אתה משתמש ב-Entity Framework (EF), ודא שכל המיגרציות של הדאטהבייס קיימות:

אם יש מיגרציות שלא הוספו עדיין, יש להריץ את הפקודה:

dotnet ef migrations add InitialMigration


לאחר מכן, יש להחיל את המיגרציות על הדאטהבייס:

dotnet ef database update

5. הגדרת המשתמשים וההרשאות:

ודא שהמשתמשים הנדרשים לדאטהבייס (כגון sa או כל משתמש אחר) קיימים ויש להם את ההרשאות המתאימות, גם אם מדובר במערכת SQL Server.

6. בדיקת החיבור לדאטהבייס:

לאחר שהכל מוגדר, יש לוודא שהחיבור לדאטהבייס פעיל.

ניתן לבדוק את החיבור דרך הקוד של ה-backend (למשל בקרת API שמבצעת שאילתה פשוטה).

אם כל השלבים הללו בוצעו בהצלחה, הדאטהבייס אמור לפעול כראוי עם שאר המערכת.

1. SQL Server (Backup and Restore)

אם אתה משתמש ב-SQL Server, אפשר להשתמש בפקודות הבאות לשחזור או העתקת דאטהבייס:

יצירת גיבוי (Backup):
BACKUP DATABASE YourDatabase
TO DISK = 'C:\Users\Pnini\Documents\מקצועות\מסלול\כל הפרוייקטים\.net angular\YourDatabaseBackup.bak'
WITH FORMAT;


שחזור דאטהבייס (Restore):
RESTORE DATABASE YourDatabase
FROM DISK = 'C:\path\to\backup\YourDatabase.bak'
WITH REPLACE;
